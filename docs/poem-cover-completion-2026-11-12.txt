PRESERVATION AND DELIVERY

The nine changed guide payloads differ only in guide.version (1 to 2) and the
addition of poem.coverImage. Every original guide, poem, stanza, line, chunk,
session and page ID is preserved. All existing wording, memorisation rounds,
recaps, metadata, poem transcriptions and approved/exported statuses are retained.
The seven previously illustrated guide files and their PNGs were verified
unchanged using checksums. Journey files and versions are unchanged.

Canonical files remain under exports/curated_poems/; the existing guides/json/
symlinks still resolve to the same files. No approved content was copied into
the Flutter tree. No generation integration was added to the application.

The new artwork and nine updated guides are packaged in:
output/remaining-poem-covers-2026-11-12.zip
The archive mirrors the canonical export structure and includes the individual
briefs and this note. It contains the nine additions, rather than duplicating
the seven earlier illustrated guides.

VALIDATION

All nine new paintings were inspected at full resolution and as 360 × 240 card
previews made from the final saved files. The subjects remain readable at card
size. Figures, animals, botanical forms and landscapes are coherent; light and
colour are restrained and appropriate to each subject. The Second Coming uses
the poem's deliberate human-headed-lion image, painted in a symbolic historical
tradition rather than a digital fantasy style. No embedded typography, logos,
signatures or watermarks are visible.

Every one of the 16 cover references resolves to its adjacent image. PNG
signatures and 1536 × 1024 dimensions were checked; new saved images match the
generated originals byte-for-byte. Every guide validates against the JSON schema,
and every guides/json/ alias remains a canonical symlink.

Flutter's real sync_studio_content.dart validator accepts all 16 poems and all
3 Journeys, including their asset and poem references. The backend test suite
passes: 124 tests. Code and whitespace checks pass.

Several version-flow tests used the live Tyger export as a version-1 test seed.
Now that the actual guide is version 2, those isolated test fixtures explicitly
start at version 1. This preserves their existing version-update, conflict and
restore assertions without changing production loading or publishing behaviour.

The running Studio database and Flutter content pin were not overwritten. Normal
Studio refresh/startup can load the higher guide versions through its existing
version workflow while protecting unsaved edits. For a release build, commit and
push approved Studio exports before advancing Flutter's pinned Studio revision.
