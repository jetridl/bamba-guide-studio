STUDIO SUPPORT

Studio's guided-plan schema now matches the Flutter app's current schema, including optional poem.coverImage. Import, storage and export preserve that field. Alembic migration 0007_poem_cover_image adds a nullable JSONB field to poems; normal backend startup applies it. Rebuild/restart the backend when taking this code update. Existing poems without a cover remain valid.

The exporter also preserves an imported authored version when working on Studio's version-0 copy, instead of silently resetting it to 1. Tests cover a version-2 guide and reject cover paths containing folders, URLs or unsupported formats.

These files are ready for the Studio content publishing workflow. A running Studio database is not silently re-imported or overwritten by this task. As always, do not re-import a guide with in-progress Studio edits. When publishing an already-held Studio copy, make sure it contains the cover reference and version intended for release before replacing the canonical export.

FLUTTER UPDATE BEHAVIOUR

The inspected Flutter code loads bundled covers separately from locally stored plans. At startup it refreshes authored plans with a higher guide.version, except for poems still in the Igniting stage (including an archived Igniting plan). That safeguard preserves resumable learning; their bundled covers can still load. Other updates preserve lifecycle history.

Release builds consume a pinned Studio commit, not uncommitted work. Commit and push the approved exports here before advancing the Flutter app's content pin. A deliberately selected local Studio worktree can be used for development. This task does not commit, push or change that pin.
